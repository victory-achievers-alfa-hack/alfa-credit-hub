# Альфа / Поток

Умный кредитный кабинет предпринимателя и рабочее место сотрудника банка. Проект демонстрирует полный путь от подбора продукта до банковского решения, подписания и моделируемой выдачи.

## Что реализовано на frontend

- интерфейс на React, TypeScript и официальной `@alfalab/core-components`;
- ролевая маршрутизация клиента и сотрудника банка;
- тестовый вход для четырёх профилей;
- главная клиента с финансовыми показателями;
- профиль бизнеса, реквизиты и синтетические документы;
- подбор продукта по цели, сумме и сроку;
- объяснение платежа, покрытия и рекомендуемой суммы;
- создание и хранение заявки;
- список заявок и детальная история статусов;
- банковская очередь, проверки, скоринг и четыре типа решения;
- альтернативный оффер, запрос сведений, отказ и одобрение;
- принятие предложения, демоподписание и моделируемая выдача;
- клиентские уведомления и счётчик непрочитанных событий;
- realtime-синхронизация заявок и уведомлений;
- общий плавный `SegmentedControl` для фильтров и выбора срока;
- адаптивный интерфейс и SPA fallback для Nginx;
- production-сборка, Dockerfile и документация интеграции.

## Быстрый запуск

### Единый запуск в Docker (рекомендуется)

Запуск всех сервисов (`backend` + `frontend` с проксированием `/api/` через Nginx и постоянным томом SQLite):

```bash
docker compose up --build
```

- Приложение (Frontend + Nginx proxy): `http://localhost` (порт `80`, либо `FRONTEND_PORT`)
- Backend API напрямую: `http://localhost:8000/api/v1` (порт `8000`, либо `BACKEND_PORT`)
- Swagger / OpenAPI: `http://localhost:8000/docs`
- Healthcheck: `http://localhost:8000/api/v1/health`

Backend-образ собирается в двухступенчатом `backend/Dockerfile` на базе `uv` (`python3.12-alpine3.23`) с упаковкой приложения через `PyInstaller` в единый исполняемый файл `/app/main` и запуском от непривилегированного пользователя в минимальном образе `alpine:3.23`. При первом старте база данных автоматически инициализируется демонстрационными данными.

### Локальный запуск Backend

Установить зависимости из корня проекта:

```bash
uv sync
```

Запустить сервер напрямую через `backend/main.py` (запускает `uvicorn` на `0.0.0.0:8000`):

```bash
uv run python -m backend.main
```

Либо в режиме разработки с автоперезагрузкой:

```bash
uv run uvicorn backend.main:app --reload
```

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`

### Тестирование Backend и DS-модулей

Из корня репозитория (Python 3.12+):

```bash
uv run pytest backend/tests/test_workflows_api.py -v
uv run python -m unittest discover -s tests -v
uv run python -m examples.financing_demo
```

Реализованы объяснимый скоринг по правилам, предварительная оценка финансирования с альтернативной суммой, ранжирование предложений, стресс-сценарии выручки, а также полный серверный API (аутентификация, профиль, каталог, рекомендации с аудитом, жизненный цикл заявок, банковские решения, уведомления и WebSocket).
План DS — [docs/ds_plan.md](docs/ds_plan.md), контракт — [docs/financing_contract.md](docs/financing_contract.md), соответствие заданию — [docs/ds_requirements_trace.md](docs/ds_requirements_trace.md).

### Frontend и realtime

Сначала запустите backend на `127.0.0.1:8000`, затем:

```bash
cd frontend
npm install
npm run dev
```

- Frontend: `http://localhost:5173`
- API и WebSocket проксируются Vite на `http://127.0.0.1:8000`
- HTTP-база по умолчанию: `/api/v1`
- WebSocket: `/api/v1/realtime`

Отдельный `npm run realtime` больше не нужен для основного приложения. Папка `frontend/realtime-server` оставлена только как изолированный demo-relay и smoke-тест протокола. Источником истины являются backend и БД; fallback на `localStorage` отсутствует.

## Как проверить realtime

HttpOnly-cookie общая для всех вкладок одного browser profile. Поэтому для одновременной проверки двух ролей используйте два независимых контекста браузера: обычное окно и инкогнито либо два разных профиля.

1. В первом профиле войдите клиентом, например `vector@demo.ru` / `123456`.
2. Во втором профиле войдите сотрудником `bank@demo.ru` / `123456`.
3. В банковском профиле откройте `APP-2026-003` и примите решение.
4. В клиентском профиле должны появиться новый статус и уведомление без перезагрузки.
5. Разорвите соединение и восстановите его: frontend переподключится, а polling раз в 15 секунд останется резервом.

## Текущее состояние backend

Backend уже стал серверным источником истины. Реализованы:

1. серверная авторизация через HttpOnly-cookie/Bearer и проверка ролей;
2. модели пользователей, компаний, продуктов, заявок, решений, событий и уведомлений;
3. API профиля, каталога, рекомендаций, заявок и банковской очереди;
4. расчёты платежа, покрытия, rule-based скоринга и рекомендуемой суммы;
5. централизованные переходы статусов;
6. уведомления и аутентифицированный WebSocket;
7. seed-данные, Docker Compose и API/расчётные тесты.

До production остаются миграции и PostgreSQL, отзыв серверных сессий, защита demo/reset и mock endpoint'ов, realtime после каждой мутации, загрузка новых документов, идемпотентность/конкурентные операции, унификация OpenAPI-ошибок и настройка HTTPS/секретов.

Полный контракт: [`frontend/INTEGRATION.md`](./frontend/INTEGRATION.md). Актуальный аудит команды: [`docs/team-progress-review.md`](./docs/team-progress-review.md).

## Что ожидается от аналитика

Нужно окончательно зафиксировать:

1. Каталог продуктов, диапазоны сумм, сроки и демонстрационные ставки.
2. Формулы аннуитетного платежа, коэффициента покрытия и скоринга.
3. Канонические статусы и допустимые переходы.
4. Кто выполняет переход `ready → disbursed`.
5. Что именно клиент отправляет в состоянии `need_info`.
6. Когда решение автоматическое, а когда обязательно ручное.
7. Правило расчёта альтернативной суммы.
8. Обязательные причины отказа и тексты предупреждений.
9. Финальные seed-данные компаний «Город», «Зёрна» и «Вектор».
10. Приоритет ИИ-помощника и новостей после основного кредитного пути.

## Что ожидается от всей команды

- backend и frontend используют одинаковые DTO и коды статусов;
- изменения контракта сначала фиксируются в OpenAPI;
- три обязательных сценария проходят end-to-end;
- Docker-сборка проверяется на чистой машине;
- перед сдачей выполняются `npm run lint`, `npm run build`, `npm run realtime:test` и ручной smoke test двух ролей.
