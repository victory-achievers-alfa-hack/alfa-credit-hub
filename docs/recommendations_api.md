# API рекомендаций и границы интеграции

Реализованы POST /api/v1/recommendations, типизированные Pydantic DTO и сервис вызова расчётов. Это замена прежнего endpoint с user_id в query и пустым телом сервиса. Внешний ответ теперь объект с группами, а не прежний планируемый список Recommendation: frontend требует адаптации.

## Текущее состояние

Сервис вызывает реальные score/financing/ranking модули и сохраняет неизменяемый аудит (`RecommendationAudit`) в БД через `SQLAlchemyRecommendationStore` до возврата ответа. Подключены серверная аутентификация (`Bearer` и `HttpOnly` cookie `access_token`) и чтение профиля компании/каталога из БД. Никаких доверенных заголовков `X-User-Id`, query `user_id`, фиктивной сессии или silent demo fallback нет.

## Запрос и ответ

```json
{"purpose":"goods","amount":800000,"termMonths":24,"preference":"min_interest"}
```

companyId необязателен; если передан, должен совпадать с компанией аутентифицированного Actor. Финансы, score, каталог, время и версии от клиента не принимаются. Лишние поля запрещены. amount: положительное число/десятичная строка, до двух знаков, <= 1e12; bool запрещён. termMonths: строго целое 1–120. Предпочтения min_interest/min_payment.

Ответ содержит evaluationId (UUID), companyId, calculatedAt UTC, rankingVersion, preference, параметры запроса и пять групп из ranking_contract.md. evaluationId идентифицирует расчёт, не заявку. Повторные запросы создают отдельные записи; это не idempotency key. Финансовые результаты при одинаковых входах и времени воспроизводимы, идентификаторы разные.

Коды: 401 AUTH_REQUIRED; 404 COMPANY_NOT_FOUND одинаков для отсутствующей и чужой компании; 409 SOURCE_DATA_INVALID (нужно уточнить серверные данные, не кредитный отказ); 503 при недоступном источнике, невалидном результате или невозможности сохранить аудит. Доменные ошибки имеют detail:{code,message}; 422 использует штатный формат FastAPI detail:[...]. В ответ не включаются внутренние исключения хранилища. OpenAPI формируется из моделей; docs/openapi_recommendations.json описывает только этот роутер, не всё приложение.

## Подключение backend

1. Реализовать проверку серверной сессии/подписи токена и клиентской роли. Заменить dependency get_recommendation_actor на провайдер Actor(user_id, company_id) в composition root. Не принимать эти значения из непроверенных заголовков.
2. Реализовать RecommendationStore.load_authorized_snapshot: повторно проверить право actor на компанию в хранилище, прочитать согласованный снимок финансов/каталога с непустыми версиями. Вернуть None и для отсутствия записи, и для отсутствия прав. Snapshot должен содержать JSON-совместимые значения; денежные Decimal преобразовывать в десятичные строки без потери точности. Продуктовый DTO содержит только публичные разрешённые поля.
3. Реализовать save_audit с атомарной транзакцией, уникальным evaluation_id и commit до возврата. Ошибка должна распространяться в сервис. Не использовать no-op/in-memory реализацию вне тестов.
4. Добавить миграцию для immutable audit record: evaluation_id, company_id, actor_id, calculated_at и JSON записи, индексы для поиска по компании/времени. Настроить права чтения, срок хранения и защиту финансовых данных. Аудит не писать в общедоступные логи.
5. Подключить frontend и сценарий заявки. При создании заявки повторно проверять текущие данные и условия либо применять явную политику срока действия оффера. Нельзя считать старый evaluationId бессрочным одобрением.

Аудит содержит полный входной снимок, запрос, версии профиля/каталога/всех расчётных правил, результат и SHA-256 канонического JSON входов. Хеш помогает выявлять случайное изменение входа, но не является подписью и не заменяет права доступа. Для повторения нужен сохранённый calculatedAt и соответствующая версия кода; одного номера версии без сохранения сборки недостаточно.

## Проверка

После установки зависимостей backend и `python -m pip install -r tests/requirements.txt`:

```bash
python -m unittest discover -s tests -v
```

HTTP-проверки используют FastAPI TestClient и тестовое хранилище. Проверены 401, запрет подмены финансов и чужой компании, 422, невалидные серверные данные, отказ аудита, структура OpenAPI и повторение расчёта. Постоянная БД и настоящая авторизация этими тестами не проверяются.

В текущей среде проверено на Python 3.13, FastAPI 0.136.1, Pydantic 2.13.4, httpx 0.28.1. Это не совпадает с более высокими минимальными версиями pyproject.toml: проверка на окружении uv.lock остаётся обязательной перед общей интеграцией. Зависимости проекта не понижались.
