# Сводка DS для команды

Состояние на 23 октября 2026. Реализованы скоринг компании, оценка конкретного кредита, альтернативы, ранжирование, сценарии чувствительности и слой API. Реальная авторизация, серверные источники профилей/каталога, постоянное сохранение аудита и frontend ещё не подключены. Нельзя говорить, что вся функциональность уже работает на стенде.

## Что можно рассказать команде

«Разработал объяснимый скоринг по правилам без обучения на выдуманных метках. Балл 0–100 вычисляется из четырёх факторов, каждый вклад раскрывается. На его основе отдельный модуль проверяет конкретный продукт, сумму и срок: считает платёж, переплату, покрытие и ограничения. При возможности предлагает проверенную меньшую сумму. Подбор перебирает сроки каталога, отделяет полную сумму от альтернатив и сортирует по предпочтению клиента. Подготовлены DTO, OpenAPI, сервис расчётов и интерфейс обязательного аудита. Проверено 40 тестами, включая HTTP с тестовыми провайдерами. Для работы в приложении нужно подключение backend-хранилища, авторизации и UI».

## Вопросы и честные ответы

- **Есть ML?** Обучаемой модели нет. ТЗ допускает правила; реальных наблюдений дефолта нет. Score не PD.
- **Это только скор кандидата?** Нет. Компания оценивается отдельно, затем каждый кредитный вариант проходит финансовый расчёт и политику. Высокий балл не отменяет просрочку и другие ограничения.
- **Откуда пороги?** Веса, 70 баллов и покрытие 1.25 — выбранная командой демонстрационная политика, не норматив Альфа-Банка и не эмпирически подтверждённые пороги.
- **Что с объяснениями?** Вклад каждого фактора точный относительно формулы. summary пока описывает категорию; полноценные персональные рекомендации ещё предстоит сделать. positive — минимум половины возможных баллов фактора, а не оценка причинного эффекта.
- **Аудит уже в БД?** Нет. Подготовлены снимок входов, версии, результат и хеш; сервис требует успешный save_audit. Постоянный адаптер отсутствует. Тесты используют FakeStore.
- **Endpoint доступен пользователю?** Без адаптера авторизации отвечает 401, без store после авторизации — 503. Непроверенный user_id/header не включает доступ.
- **Готово для production?** Нет: требуются авторизация/RBAC, БД и миграции, актуальность/происхождение данных, наблюдаемость, политика хранения, интеграционные проверки и настройка окружения.
- **Как проверяли?** 40 тестов: формулы, округление, граничные случаи, изменения финансов, блокировки, альтернативы, ранжирование, сценарии, HTTP и ошибки аудита. Не измерялась способность предсказывать реальные дефолты. Версии доступного тестового окружения отличаются от pyproject.toml — подробности в recommendations_api.md.
- **Что дальше?** Подключить реальные backend-провайдеры и хранение, адаптировать frontend, перепроверять актуальные условия при создании заявки, выполнить сквозные тесты. Параллельно можно улучшить персональные объяснения без обещаний одобрения.
